# 用 Qwen3-VL-8B-Thinking 恢复 V2.1 完整 episode

## 总结

同意将 **Qwen3-VL-8B-Thinking 作为 V2.1 主模型**。保留小 agent 负责语义与空间关系判断、runtime 负责动作授权的架构。先让 V2.1 关键节点真正调用 Thinking，再检验双次反思是否改善决策；最终成功只按 `env.check_success()` 计。

## 模型与双次反思

- 在 V2.1 隔离配置使用独立的 Thinking 服务。先以真实最大多图请求核对模型 ID、显存、延迟、推理字段及完整最终 JSON，再跑**单轮 Thinking 基线**。现有 V2.1 关键调用不会因更换模型名自动启用推理，需显式接通推理预算。
- 双次反思沿用已确定的触发：首次准备闭爪、每次闭爪后的持握核验、每个 route epoch 首次下降、动作无进展或证据冲突、每次放手前。普通单步修正只调用一次；同一冻结证据最多触发一组两轮调用。
- 第一轮 Thinking 看当前原始双视角与本 episode 的相关 visual memory，输出带帧号的**可见事实、动作前后变化、反证和缺失观测**，不选动作。第二轮重新看**完全相同的图像与记忆**，再加入第一轮的结构化最终答案、工具证据及 runtime 允许的选项，输出状态假设、支持与反对证据、所选选项和预期效果。
- 两轮各自可以使用模型推理，但传给下一轮及 runtime 的只有通过校验的**最终结构化答案**。推理文本不进入动作授权；第一轮答案也不能冒充独立物理证据。若两轮证据冲突、引用过期、最终答案为空或生成截断，runtime 返回 `UNKNOWN` 并要求重新观察或有界取证。[vLLM 推理输出说明](https://docs.vllm.ai/en/stable/features/reasoning_outputs/)

## 实施与验收

- 先运行 V2.1 单轮 Thinking 的 `LIBERO_OBJECT / task 2 / init 0 / seed 0` episode，检查视频和原始双视角，标出首个错误分叉；再接入双次反思，使用相同任务配置比较。记录两轮实际图像 hash、结构化答案、token/延迟及请求、授权、执行动作。
- 修正 V2.1 已知的方向探测与持握判据；VisualRoute 和放置 reviewer 只提供证据及建议，最终动作统一由 runtime 授权。持握须有闭爪后的视觉与有界动作效果核验，放手须有新鲜落座证据。
- 用冻结失败帧比较单轮与双轮在抓取、持握和放置疑点上的判断，并检查无效引用、重复无进展及矛盾回答。真实 rollout 每次只跑一条，按最早错误分叉修复；出现首次 `env.check_success() == true` 后，再做重复运行和另一物体验证。每轮结果写入 `docs/revolution`。

## 默认约束

使用本地独立的 **8B-Thinking 权重**，不是给 Instruct 打开模板开关。初始服务设置采用 16K 上下文、单请求最多 4096 个生成 token、关键调用最多 1024 个推理 token，并以完整多图服务测试确认可用。正式策略的 visual memory 严格限于当前 episode；模拟器真值和 `check_success()` 只用于隔离诊断与最终评分。
