# V2.2 放置阶段的 Visual Memory 闭环

## 当前判断

Visual memory **尚未真正以历史视觉记忆的形式送到 Qwen**。Runtime 创建了记忆条目，但没有填写图像引用；最新 rollout 的抓取前请求和 step 178 放置核验请求中，`visual_memory_refs` 都是空数组。抓取前 Qwen 看到的“前后帧”是临时图板；放置核验只收到当前双视角和几何证据。

step 178 还有独立的判断偏差：下降没有确认 stall，微弱的二维重叠却被升级为 `RIM_CONTACT`，并作为既定关系写入 Qwen 输入。Qwen 返回同一关系后，系统进入升降循环。历史图像可能帮助判断，但不能代替接触证据和 release 门槛。

## 实施方案

- 修通记忆链：按 grasp epoch 保存少量关键节点的**原始双视角**、帧号、实际执行动作及其观测效果、route phase、几何不确定性和先前核验结果。用真实 action receipt 更新记忆；请求发出前检查图像引用可解析，并记录 Qwen 实际收到的图板与请求元数据。修正当前 `qwen_input` 日志保存成 overlay 的问题。
- 在进入 seating、首次接触疑点、clearance 恢复后或连续动作效果异常时，最多触发一次对应事件的反思；每次选不超过两个相关历史节点，加当前帧。冻结这次观测，期间不执行环境动作，避免两次调用使用不同状态。
- 将双次反思做成 V2.2 可配置实验：第一次让 Qwen 仅依据原始时序图像和真实动作效果，输出带帧号依据及 `UNKNOWN` 项的结构化场景描述；第二次把**同一图板**、描述和最新 placement belief 交给 Qwen，只输出既有 `PlacementRelation`。首次调用不预填 provider 的关系标签，减少锚定。
- 修正接触与放手协议：二维重叠仅触发“需复核”的疑点，不能单独生成 `RIM_CONTACT`；真实下降 stall 或跨帧、跨证据的一致接触才可升级。Qwen 的 `SEATED_HELD` 也必须通过新鲜身份、包含关系、下降后支撑与稳定性证据的 runtime 门槛，才能进入 release。动作权继续只在 VCR runtime。

## 验证顺序

1. 用现有三次 rollout 的保存帧离线回放，先验证图像引用、时序顺序、实际动作效果及 Qwen 输入日志完全一致；补充空引用、过期帧、实例切换和上下文超限的回归测试。
2. 对相同关键帧比较当前单帧、一次带记忆判断、双次反思三种输入；记录错误的确定性接触判断、错误 seated 判断、`UNKNOWN`、延迟和 token。若双次反思没有改善，线上采用一次带记忆判断，保留双次方案供后续评估。
3. 为 step 178 建立回归：`contact_candidate=true` 且 `stall=false` 时不得直接抬升或放手；证据不足时停止或在满足安全前置条件后执行一次有新观测的有界下降。
4. 离线门槛通过后再恢复单 episode；验收为真实出现 `SEATED_HELD → VERIFY_SEATED → OPEN_GRIPPER`，且 `env.check_success()` 成功。随后按现有路线做同一 init state 的 5 次统计和其他物体验证。每阶段同步更新 `progress.md` 与 `route.md`。

## 默认约束

只改 V2.2；不使用对象名称、固定坐标或尺寸作为判据。模拟器真值仅用于离线诊断。当前 rollout 暂停状态保持到离线接口与安全门槛验证完成。
